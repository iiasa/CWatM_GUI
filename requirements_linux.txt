# CWatM GUI - runtime dependencies
#
# The pins reproduce the working venv used to run and build CWatM_GUI on
# **Windows / Python 3.12**. Install with:
#     python -m venv venv
#     venv\Scripts\activate
#     pip install -r requirements.txt
# For the PyInstaller executable build, then also: pip install -r requirements_build.txt
#
# --------------------------------------------------------------------------------
# LINUX / other Python versions (e.g. 3.13): the same file works, with two provisos.
#   1. Install wheels only, so a package without a wheel for your interpreter fails
#      loudly instead of silently starting a source build:
#          python3 -m venv venv2 && . venv2/bin/activate      # needs python3-venv
#          pip install --only-binary=:all: -r requirements.txt
#      If one package has no wheel for that Python, relax **that** pin (e.g.
#      PySide6>=6.8) and leave the rest alone. Nothing in the GUI or in cwatm/ uses
#      a stdlib module removed in 3.13, so the interpreter itself is not the issue.
#   2. Ignore the *.whl files lying in the repo root (rasterio / netCDF4 / GDAL):
#      they are cp312 **win_amd64** wheels for this Windows venv. On Linux pip takes
#      the manylinux wheels from PyPI - do not point anything at those files.
# Optional blocks that can be dropped if unused: playwright (CWatM AI login window)
# and flopy/matplotlib/xmipy/bmipy/black (MODFLOW coupling).
# Start the GUI with ./gui.sh (see its header for the remote-X11 settings).
# --------------------------------------------------------------------------------
#
# --------------------------------------------------------------------------------
# IMPORTANT - GDAL: do NOT install the separate `GDAL` / `osgeo` wheel.
# The rasterio wheel below ships its OWN GDAL (in a `rasterio.libs/` folder). This
# venv previously had a GDAL-less rasterio that borrowed its GDAL DLL from the osgeo
# wheel; removing GDAL then broke rasterio ("ImportError: DLL load failed while
# importing _base"). A clean `pip install rasterio==1.5.0` from PyPI gets the wheel
# WITH bundled GDAL and needs no osgeo. If rasterio ever imports with that error,
# reinstall the self-contained wheel:  pip install --force-reinstall --no-deps rasterio
# --------------------------------------------------------------------------------
